Notable changes to requirements, documentation structure and the product, newest first. Each entry says what changed and links to the decision or evidence.

## 2026-10-01

### Product (completion session)

- **Couple Spaces.** A new private Space type for two people: the person who creates it and one partner they invite. The creator can use it at once, and it says "Waiting for your partner" until the partner joins, then "With" and their name. Only one invitation can wait at a time, and a third person is refused by the server and by the database. Either person can leave (the owner after handing ownership over), and the owner can remove the partner; a new partner then sees nothing from before. On backend, web and Android; migration `0025` ([T12](docs/TASKS.md#approved-requirements-not-built-yet); [DEC-017](docs/DECISIONS.md#accepted-decisions), provisional until you review it; [checkpoint](docs/BUILD_STATUS.md#couple-spaces-and-space-privacy-checkpoint)).
- **Group Spaces finished.** The build session's group Spaces (T22) were closed: Android now lets the owner edit a Space's description too, as the web does, and every live Space journey passes again.
- **A private Space now looks exactly like a missing one** to anyone who is not a member, on every operation that names a Space ([T42](docs/TASKS.md#defects-that-break-approved-requirements)). Leaving or removing used to answer "Membership not found" instead of "Space not found"; an independent review then found four more differences (an ownership offer, answering an offer after leaving, revoking a known invitation, deciding a known join request), all fixed. A former member can still repeat their own confirmed leave.
- **Changed tests** ([Article 7](docs/PRODUCT_CONSTITUTION.md#article-7-protecting-existing-behaviour)): four tests said a couple Space could not be created. Because DEC-017 now allows it, they check instead that an unknown type and a public couple are refused.
- **Documents in private Spaces.** In a family, solo or group Space, a member can add a text document (`.txt`, `.md` or `.csv`, up to 512 KB), open it with numbered lines, and the person who added it or the owner can delete it after a confirmation naming the document, who added it and the Space. Deleting removes its name, text and everything derived from it at once. People who join later do not see earlier documents, as in chat and events. Other file types wait for a virus-scanning decision. On backend, web and Android; migration `0024` adds 2 tables ([T14](docs/TASKS.md#approved-requirements-not-built-yet); [checkpoint](docs/BUILD_STATUS.md#space-documents-and-search-checkpoint)).
- **Search inside your Spaces.** One search finds the documents, tasks and events you can open now, in all your Spaces or one: every word must match, from the start of a word, and a document result opens the document with the cited lines marked. Messages, care records, reminders and agent memory are not searched. Web: Search in the header; Android: Search on the account screen ([T15](docs/TASKS.md#approved-requirements-not-built-yet); step 2 of the [end-to-end plan](docs/TASKS.md#end-to-end-plan)).
- **Decisions recorded:** [DEC-015](docs/DECISIONS.md#accepted-decisions) (what documents and search do, provisional) and [DEC-016](docs/DECISIONS.md#accepted-decisions), which records your delegation in this session ("I'm giving full permissions to you … if anything didn't mention properly then try to work on it") and resolves the rule part of conflict C11. DEC-010 to DEC-012 still wait for you.
- **Checks:** backend 9 new tests, and 10 deliberately injected mistakes each made them fail; web 13 client tests and 7 offline screen tests; the live web journey passed; Android 30 new JVM tests (234 in total, all passing), lint 0 errors, both builds; on the emulator the 7 new screen tests passed and a live journey searched, opened and deleted a document against the local API. A blind security review by a second model led to one fix (a deleted document no longer keeps a fingerprint of its text), and a visual review of live screenshots by a third model led to four (forms no longer framed as cards, the document comes first when open, the delete confirmation names who added it, no repeated sentence on an empty search).
- **Live locally:** the development database is at `0024` and the shared API was restarted at about 14:35, which also made the agent backend (`0023`) live.

### Product (audit session)

- **Reminder request lists work from the keyboard** (T55): on the web, Received and Sent are proper tabs. The arrow keys, Home and End switch between them, Tab stops only at the open one, and screen readers hear which list is shown.
- **"Pages you follow" no longer says you follow nothing when it could not load** (T56): it shows that the list is loading, shows the empty message only after a successful load, and a failed load shows the error with Retry.

The API's readiness check reports not ready while the database lacks migrations the code needs, and stays ready for a database that a newer release has migrated.
- **Documents brought up to date with the code** (T53): the Product Understanding now matches the code for group and couple Spaces, documents and search, and the agent backend (requirements R5, R6, R7, R8, R10 and R11; gaps G5–G7). The two alternate Chapter 19 and 20 drafts now say that all 14 of their decision IDs mean something different from the working drafts. Alert statuses still wait for your decision on C10.
- **Android recovers from a broken session key.** If the device's Keystore key for the session can no longer be used, the app now replaces it once instead of failing every sign-in until app data is cleared. If it still cannot store the session, it says so instead of "No connection" ([T49](docs/TASKS.md#defects-that-break-approved-requirements); [checkpoint](docs/BUILD_STATUS.md#session-keys-and-security-sweep-checkpoint)).
- **Security checks across the whole API** (T52):
  - every signed-in operation refuses anonymous calls and expired sessions;
  - every Space operation refuses non-members;
  - none of these calls changes stored data;
  - a real server process writes no private request values;
  - no secret is stored in plaintext.

  The checks found two defects, both fixed:
  - Approving or declining a join request looked it up before checking sign-in.
  - An unexpected error left the application with its message, so the server logged it with the full traceback. It now returns the standard `INTERNAL_ERROR` response, and only the error type and code locations are logged.

  Five more tests check that deleting or reading a message, and creating, cancelling or answering an event, save nothing when the session expires while the write waits for a lock. They pass on the existing re-check. The complete backend suite passed 444 of 445. The 1 failure is the group Spaces migration test, which expects `0022` to be the newest migration although the agent and documents work added `0023` and `0024`.
- **Web chat shows every message after a long absence.** If more than 330 messages arrived while the tab was hidden, the chat used to skip some and still mark them read. It now fetches what is missing over the next polls and marks read only what it fetched. Polls no longer overlap, and a deleted message stays deleted ([T41](docs/TASKS.md#defects-that-break-approved-requirements); [checkpoint](docs/BUILD_STATUS.md#web-reliability-and-text-limits-checkpoint)).
- **Long posts fit.** A post of the full 5,000 characters is no longer refused for its size, whatever characters it uses and however the client encodes it: post writes accept 64 KiB at the web proxy and the API. Emoji now count once in page names, titles and comments when the web checks what the server returned, so those saves no longer show as "not confirmed". The API description states each field's real limit (T46). `openapi.json` was regenerated; it also picked up the agent, documents and search routes other sessions are building.
- **The web proxy stops reading an oversized request.** A request without a declared size is refused as soon as it passes its limit, and a request that does not arrive within 15 seconds, or 60 for a document, is refused (T47).
- **No duplicate events from leaving an unconfirmed form.** While a new event is being saved or its save is unconfirmed, changing Space or opening another event first asks, because creating the event again could make a duplicate. Retry keeps the original key (T48).
- **Found while verifying:** 3 of the 7 offline document screen tests fail. They belong to the documents work another session is still building, and they fail the same way without these changes.
- **Web editors no longer overwrite newer changes.** Editing a page, post or event while another device changed it no longer silently undoes that change. The save is refused with "changed since you opened it", and you can reload. Before this, switching back to the tab refetched the item, and the save went through with the new version tag ([T39](docs/TASKS.md#defects-that-break-approved-requirements); [checkpoint](docs/BUILD_STATUS.md#audit-fixes-checkpoint)). 4 new web component tests failed before the fix and pass after.
- **The Android release build keeps what its API calls need.** In the release APK, R8 had stripped the type information Retrofit 2.9.0 needs, so every call would have failed before it was sent. The added rules are the ones Retrofit 2.10 ships, and the APK's bytecode now shows the full types (T40). The release build now also keeps every feature's transfer objects, including the new documents feature, and the stored session's field names.
- **The test commands run every suite.** `test:client`, `test:unit` and `test:e2e` now run every file in their folders, which adds the identity, care and alerts files the fixed lists had left out (T51). The worker recovery test's hang guard is 60 s instead of 20 s; what it checks is unchanged. [tests/e2e/README.md](tests/e2e/README.md) explains how to save a valid JUnit report: set `FORCE_COLOR=0`, because Playwright adds colour codes even with `NO_COLOR`.
- **The working tree is committed locally** as `2c1ec0c` (290 files), so the work since 2026-09-28 has a restore point. It is not pushed: the GitHub repository is public, and its visibility is your decision. `android/.kotlin/` is now ignored.
